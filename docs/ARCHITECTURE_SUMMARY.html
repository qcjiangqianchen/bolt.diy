Application Architecture Summary

Core Internal Systems & Production Data Lifecycle

This document provides a comprehensive technical breakdown of how Bolt.diy functions as an autonomous development environment. It covers the interaction between the LLM, the browser runtime, and the deployment systems.

1. The Four Behavioral Pillars

The LLM Orchestrator

Located in api.chat.ts. It uses the Vercel AI SDK to bridge your chat messages with advanced models. It injects strict system prompts and your current file context into every request.

WebContainer Runtime

A virtual Node.js operating system running in your browser tab. It handles local file system operations, runs terminal commands (npm/pnpm), and hosts the local preview server.

ActionRunner Engine

The "Hands" of the AI. It parses the incoming text stream for <boltAction> tags and real-time updates the WebContainer's files before the AI even finishes responding.

Cloud Bridge (Deploy)

Located in api.deploy-docker.ts. It packages your browser-native code into Docker images, applies analytics, and pushes the result to the Fly.io global infrastructure.

2. Data Lifecycle: Input to Production

1

Prompt Processing

The frontend gathers your current code state and sends it as a "context buffer" to the server. Your query is wrapped in rules that enforce Tailwind, strict factuality, and error-free code.

2

Real-time Execution

As the AI streams individual characters, the StreamingMessageParser identifies code blocks. The ActionRunner instantly executes file writes or shell commands in your WebContainer.

3

Hot Reload Preview

A local dev server (defaulting to port 5173) starts within the WebContainer. Bolt.diy detects this open port and automatically points the preview window to the internal proxy.

4

Deployment & Injection

When you click 'Deploy', the server receives your files. Crucially: It searches for </body> in your HTML and automatically injects a tracking beacon script for analytics before packaging the Docker image.

5

Production Analytics

Your app goes live on fly.dev. Every visit pings /api/stats (in api.stats.ts). This records the app name, path, and session ID anonymously to update your dashboard.

3. Technical Nuances & Discovery

One of the most unique aspects of the architecture is the "Shadow Metadata" injection. Because analytics are injected during the deployment middleware rather than written by the AI, the source code you see in the editor remains "clean," while the production site is fully instrumented for tracking.

Additionally, GrapesJS Integration works by observing code changes and dynamically pulling the generated Tailwind CSS from the WebContainer's virtual terminal and injecting it into the GrapesJS iframe, solving the isolation problem typical of visual builders.
